# Подготовка и сдача 11.09

## Период и исходные данные

Начало AIOS, число интервалов, число дат полного дека и базовый год дисконтирования
задаются в JSON по образцу [config/horizon-model-z.json](config/horizon-model-z.json).
Укажите `AIOS_HORIZON_PATH` **до запуска Python**. Значения по умолчанию сохраняют
учебный Model_Z: 01.01.2007, 224 интервала, 371 дата. Поддерживается месячная сетка.
Год дисконтирования нужно взять из окончательной методики; не выбирать ради роста ЧДД.

Пятничный дек и нормативы подключаются через `AIOS_DOCS_ROOT`, ограничения — через
`--case`. Текущий competition-constraints.json не заменяет пятничное задание.
Если даты новых данных не совпадают с контекстом обученных весов, поиск откажется
работать. Настройка горизонта не переобучает суррогат: нужны совместимые веса,
матрица связности и отклик базы. Проверка OPM остаётся источником заявленного ЧДД.
Резервный режим `--direct-only` не загружает веса: сначала измеряет базу в OPM,
затем проверяет режим без закачки и постепенно увеличивает её по измеренной воде
последнего допустимого лидера. Уставки в интервалах с измеренными нарушениями
давления уменьшаются. Доли воды задаёт `--water-margins` (по умолчанию 0, 0.85, 0.95).
Каждая проба требует новой проверки OPM. Нужны дек, нормативы,
ограничения и матрица связности для формирования проверяемых участков.
Если базу нельзя запустить даже статически, этот режим не выдумывает её отклик.

В предварительном кейсе внешняя вода равна нулю. По документации проекта значение
`n` выдаётся в тестовом кейсе: после его получения нужно заменить ограничение и
заново пересчитать базу. Результат при n = 0 не является финальным ЧДД на неизвестном
пятничном кейсе. Уменьшение закачки меняет добычу попутной воды, поэтому ограничивать
новый режим водой старой, недопустимой базы недостаточно — это проверяется OPM.

## Кампания на совместимом кейсе

```bash
export AIOS_DATA_ROOT=/absolute/path/to/data
export AIOS_SURROGATE_MANIFEST="$AIOS_DATA_ROOT/surrogate-production.json"
export AIOS_LAMBDA_PATH="$AIOS_DATA_ROOT/lambda-window-2007/lambda.json"
export AIOS_HORIZON_PATH="$PWD/config/horizon-model-z.json"
python -m backend.presentation.cli.final_campaign \
  --case config/competition-constraints.json \
  --root out/final-campaign-01 --evaluations 120 --opm-budget 8 --rounds 3
```

Если кандидаты ушли за область обучения, используйте `--direct-only`. Для продолжения
той же кампании добавьте `--resume`. Бюджет OPM задаёт общий предел кампании, включая
уже законченные проверки. Отказы, отклики OPM и лучший пригодный пакет сохраняются.

Новая кампания требует нового каталога. Прерванную кампанию можно продолжить с `--resume`:
горизонт и ограничения должны совпадать, готовые результаты и кэш сохраняются.
Вначале проверяется исходная база, если она статически допустима. Затем суррогат ранжирует перераспределение закачки
по связности и изменения уставок отдельных скважин на разных отрезках времени.
Лучшие разные расписания проходят OPM. Следующий раунд ищет около подтверждённого
лидера. `--global-search` дополнительно запускает CMA-ES в каждом раунде.
Для смешанных изменений инварианты, определённые только для изменения закачки,
не являются критерием отказа от OPM-пробы. Кампания явно записывает непроверенную
физику прогноза. OOD и базовая корректность выходов модели проверяются, а
допустимость кандидата и заявленное число всегда устанавливает настоящий OPM.
Для отдельного глобального поиска доступны `run search --budget 120 --seed 42`.

`champion.json` обновляется атомарно только после допустимого OPM, сборки подачи
и проверки её хешей, если ЧДД вырос. Сравнение требует одинаковых ограничений,
дека, нарезки участков, методики, экономической конфигурации и образа OPM. Ошибка последующего
прогона не стирает уже сохранённого лидера. Прогноз не заменяет измеренное число.
`evaluations.json` объясняет отказы и результаты. При отсутствии допустимого
лидера команда завершится с кодом 2; это не готовность к сдаче.

## Что отправлять

Путь к пакету лидера указан в `champion.json`, поле `submission`.
Организатору отправляются **well_schedule.inc** и число `claimed_npv_rub`
из claimed_npv.json. Include содержит только даты начиная с AIOS;
его нужно включать после истории организатора. Повторных WELSPECS и
искусственной даты до AIOS в нём нет.

Для локальной проверки история сохранена отдельно в validation/history.inc.
Конкатенация этой истории с отправляемым файлом побайтово совпадает с полным
include, из которого строится прогон. `selfcheck --submission` проверяет
канонический хеш в этом контексте и SHA-256 только отправляемых байтов.
Историю организатору как управляющий файл не отправлять.

Перед дедлайном: повторить лучшего кандидата на чистом OPM без кэша, проверить
экономику на окончательном расчётчике организатора, проверить пакет и зафиксировать
финальный коммит. Оставить на это минимум время двух измеренных прогонов плюс
резерв на выгрузку. После дедлайна вычислительную логику не менять.
