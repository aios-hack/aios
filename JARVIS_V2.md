Написан 2026-09-11 после разбора текущего кода. Первая версия (`JARVIS.md`, §12) закрыта
полностью — этот документ её не отменяет, а надстраивает. Контракт §11 `JARVIS.md`

Читать перед первой правкой: `CLAUDE.md`, `JARVIS.md` (§1–§4, §7, §11), этот файл целиком.

## 0. Правила на этот день

1. **Тесты не пишем.** Ни новых файлов, ни новых кейсов. Если существующий тест сломан
   намеренной правкой контракта — минимально поправить ожидание или удалить кейс, не тратя
   на это больше пяти минут. Полный прогон делает только координатор в конце волны.
2. **Моков в проде нет.** `mockTransport`, фикстуры `public/jarvis/fixtures`, `FakeChatClient`
   живут только в тестах и генераторе записей. Прод-путь: SSE к живому бэкенду; бэкенд
   недоступен — честная ошибка с кнопкой «повторить», не подмена.
3. Комментариев и докстрингов — ноль (правило `CLAUDE.md`, «Комментарии»). Импорты вверху.
   Файлы фронта ≤ 250 строк. Хексы только в `src/theme/`.
4. Три агента, у каждого свой набор файлов (§9.1). Чужие файлы не трогать; нужна правка у
   соседа — записать в §10 «Запросы между агентами», координатор разрулит.
5. Никаких git-операций у агентов. Никаких прогонов OPM без явного «да» владельца (одна
   задача C-08 помечена как ждущая решения).
6. Числа в подписях Джарвиса по-прежнему только из инструментов и найденных документов —
   сторож остаётся, расширяется (§3.4).

### 1.2 Консоль

| Симптом | Причина |
|---|---|
| Клик по вершине графа: панель гаснет вместе с фоном и не скроллится | `.jarvis-cube` несёт `transform` **всегда** (даже закрытый: `rotateY(0deg)`, `JarvisStage.css:29`). Любой `transform` создаёт контекст наложения и становится containing block для `position: fixed`. Скрим портируется в `body` с `z-index: 10` и ложится **поверх** всего куба, включая инспектор с `z-index: 20` внутри куба. Инспектор `position: fixed` привязан к кубу, обрезается `overflow: hidden` предков — `overflow-y: auto` не получает переполнения |
| Плеер ломается после Джарвиса | Та же причина: в фазах `shrinking`/`turning` на `.jarvis-face-scale` стоит `scale(0.85)`; `useBackdropShape`, `useContainerBox`, `useStageBox`, `useReadoutBounds` меряют через `getBoundingClientRect()` — получают размеры ×0.85, перерисовывают фон плеера и canvas'ы уменьшенными; `ResizeObserver` после возврата `scale(1)` не срабатывает (layout-размер не менялся) — форма остаётся кривой |
| Граф: «вершины обводятся разными формами» | Пять состояний `HighlightState` и четыре кольца одновременно: пульс (selected), группа (цветное, у всех), сосед (пунктир), ореол (`--color-oil-strong`). Плюс форма глифа = роль (круг/треугольник), полая = остановлена. Легенды нет |
| «Новый вью» с созвона | Ментор (транскрипция, 00:11:34): «в гидродинамическом моделировании рисуют карты давления и насыщенности воды, в динамике на весь период». У нас есть геометрия и свойства сетки (`Model_Z_grid.inc`: COORD, ZCORN, ACTNUM, PORO, NTG, PERMX/Y/Z; `Model_Z_regs.inc`: FIP_ZONE, EQLNUM, SATNUM), но нет рестартов OPM (`.UNRST`) и их читателя |

## 2. Целевая картина (что увидит жюри)

1. Открываешь Джарвиса — сфера **выдыхает** первую сцену без вопроса: состояние системы
   (чемпион, последний прогон, шаг, тревоги диагностики) и четыре подсказки.
2. Спрашиваешь голосом «как устроена система?» — над сферой живая расшифровка, сфера
   слушает (кромка светлеет по громкости). Ответ: карточка **карты системы** (граф
   компонентов, кликабельный), карточка `doc` с выдержкой из `ARCHITECTURE.md` и
   подпись. Джарвис отвечает голосом с настоящей амплитудой — молнии по пикам.
3. «Покажи код запуска verify» — ответ с markdown: заголовок, fenced-блок с командой из
   документации, кнопка «копировать».
4. «Что решил совет на шаге 96?» — карточка `council` из `hierarchy.json`, `rule` из журнала.
5. Над полем ввода — лента памяти: каждая сцена — бусина с вопросом; нить между ними;
   клик — сцена выезжает из глубины со всеми карточками. Перезагрузка страницы — лента на
   месте, вчерашние сессии — в выпадающем списке.
6. Выход — дверь слева снизу, там же, где вошёл.
7. В консоли: клик по вершине графа открывает читаемую, прокручиваемую панель; плеер не
   ломается после Джарвиса; на «Поле» — новая вкладка «Карты» с картами свойств пласта по
   слоям и скважинами, которые живут во времени вместе с плеером.

## 3. Контракт v2 (единственный источник правды, правится только здесь)

### 3.1 События SSE

Существующие события `JARVIS.md` §11.1 сохраняются. Добавляются:

```json
{"type":"scene","scene_id":"s-07","question":"…","context":{…},"ts":"2026-09-11T10:20:31Z","session_id":"uuid"}
{"type":"card","scene_id":"s-07","card_id":"c-02","order":2,"tool":"search_docs","args":{"query":"…"},"card":{…}}
{"type":"answer_delta","scene_id":"s-07","text":"## Как запустить\n\n```bash\n"}
{"type":"answer","scene_id":"s-07","text":"…полный markdown…","guarded":true}
{"type":"capabilities","tts":true,"stt":"server|browser|none","docs":412,"sessions":9}
```

Порядок: `scene` → (`status` | `card` | `warning`)* → `caption_delta`* → `caption` →
(`answer_delta`* → `answer`)? → `suggestions` → `done`. `answer` — необязателен: модель даёт
его только на вопросы «как/почему/что такое/покажи код», где двух фраз мало. `caption`
остаётся коротким и именно он озвучивается.

## 4. Джарвис-бэкенд: спецификация

### 4.1 Индекс документов (`backend/application/jarvis/docs_index.py`)

- Корпус: `AIOS_JARVIS_DOCS` — список корней через `;`, по умолчанию корень репозитория
  (`*.md` верхнего уровня, `config/README.md`) и `../docs` (`TASK.md`, `FINAL_PLAN.md`,
  `BACKLOG.md`, `DISCUSSIONS.md`, `checkpoints/*.md`, `*.txt` транскрипции). Плюс записи
  `glossary.json`/`guide.json` как отдельные документы.
- Чанк = раздел под ближайшим заголовком, режется на ≤ 1 200 символов с перекрытием 150.
  У чанка: `source` (относительный путь), `heading` (цепочка заголовков), `anchor`
  (slug заголовка), `text`, `numbers` (все числа в тексте, нормализованные так же, как в
  `guard.py`).
- Токенизация: нижний регистр, разбиение по не-буквам, русский стеммер обрезанием окончаний
  (список из ~40 суффиксов) + английский стемминг по `s/es/ing/ed`; для токенов короче 4
  символов — как есть. BM25 (`k1=1.5`, `b=0.75`), stdlib only.
- Кэш `out/jarvis/docs-index.json` с `mtime` и размером каждого файла; пересборка по
  изменению. Первая сборка ≤ 3 с на текущем корпусе (~650 КБ md).
- `search_docs` возвращает k хитов с подсветкой совпавших слов (`<mark>` не нужен —
  фронт подсветит сам по `terms`).

### 4.2 Карта системы (`frontend/public/jarvis/knowledge/system.json`)

Курируемый файл, пишет агент A (предметное письмо). Узлы (минимум): `console`, `jarvis`,
`web` (сервер статики и прокси, 8000), `jarvis-service` (8010), `search` (поиск
расписаний), `surrogate` (модель + NPV-head + OOD), `policy` (иерархия агентов, R0–R7),
`physics` (семь инвариантов), `opm` (Flow в Docker, закреплённый digest), `deck` (Model_Z),
`cases` (ограничения), `runs` (out/runs, манифесты), `submission` (пакет сдачи),
`webdata` (витрина), `knowledge` (глоссарий, гид, документы), `docs` (постановка и планы).
У узла: `label`, `kind` (`ui|service|domain|infra|data|doc`), `summary` ru/en (2–3 фразы,
только из `ARCHITECTURE.md`/`JARVIS.md`), `doc` (файл#якорь), `route` (маршрут консоли или
`null`), `files` (ключевые каталоги). Рёбра с подписью потока данных. Тест на существование
файлов не пишем — агент проверяет `ls` руками.

### 4.3 Промпт v2 (`prompt.py`)

Структура: роль → «что такое AIOS» (5–7 строк, собираются из `system.json` при старте) →
живой контекст (сценарий, шаг, скважина, экран, чемпион, последний прогон) → playbook →
формат → правила чисел → тон.

Playbook (обязателен, модель обязана ему следовать):

| Класс вопроса | Инструменты | Минимум карточек |
|---|---|---|
| про систему/архитектуру/«как устроено» | `system_map`, `search_docs` | 2 |
| «как запустить/какая команда/что за файл» | `search_docs` (scope `docs`) | 1 + `answer` с fenced-блоком из хита |
| про прогон/чемпиона/сдачу | `system_status`, `run_detail`, `run_history` | 1 |
| про физику/нарушения | `physics_report`, `run_detail` | 1 |
| про совет/агентов/кто решил | `council_step`, `decision_journal` | 1 |
| про скважину/фонд/деньги | как в v1 | 1 |
| термин/экран | `explain_term`/`platform_guide` (+ `search_docs` при промахе) | 1 |
| про историю диалога («что я спрашивал», «а у соседней») | память сессии, без инструментов | 0 |

Формат: `caption` ≤ 2 фраз всегда; `answer` (markdown, ≤ 1 500 символов) — только для
классов «как устроено», «как запустить», «что такое» при промахе базы и «почему» с
многошаговым объяснением. Инструменты можно вызывать пачкой в одном раунде. `MAX_TOOL_ROUNDS`
4 → 5, `JARVIS_MAX_TOKENS` 1200 → 2400, температура 0.2.

### 4.4 Сессии на диске (`session.py`, `session_store.py`)

- `out/jarvis/sessions/<session_id>/events.jsonl` — каждое событие ответа как есть, плюс
  строка `{"type":"ask","question":…,"context":…,"ts":…}` перед сценой.
- `meta.json`: `started`, `last`, `scenes`, `summary` (сжатая память старых обменов).
- Память для модели: последние 6 обменов дословно (вопрос + типы карточек + подпись +
  первые 300 символов `answer`) + `summary` старых (модель обновляет его одним коротким
  вызовом без инструментов, когда обменов становится больше 6; хранится в `meta.json`).
- При старте сервиса `SessionStore` поднимает `meta.json` всех сессий (без событий);
  события читаются лениво по `GET /sessions/{id}`.

### 4.5 Голос на сервере

- **TTS** — `edge-tts` (нейроголоса Microsoft, без ключа, нужна сеть). Голоса по умолчанию:
  `ru-RU-SvetlanaNeural`, `en-US-AriaNeural`; `JARVIS_TTS_VOICE_RU/EN` для смены. Перед
  синтезом markdown снимается (заголовки, маркеры, код → «фрагмент кода» одной фразой).
  Кэш `out/jarvis/tts/<sha256(text|voice)>.mp3`. Ответ стримится по мере получения чанков.
  Зависимость — в `pyproject.toml` `[project.optional-dependencies] jarvis = ["edge-tts>=7"]`,
  ставится в образ. Нет пакета или сети → `503 tts-unavailable`, фронт уходит на
  `speechSynthesis`.
- **STT** — через уже имеющийся ключ OpenRouter: модель с аудио-входом
  (`JARVIS_STT_MODEL`, по умолчанию `google/gemini-2.5-flash`), сообщение
  `{"type":"input_audio","input_audio":{"data":<base64>,"format":"webm"}}` + системный промпт
  «расшифруй дословно, верни только текст на языке X». Лимиты: 25 с, 2 МБ. Опционально
  `JARVIS_STT=local` → `faster-whisper` (только если останется время; не обязателен).

### 4.6 Briefing

`GET /api/jarvis/briefing` — оркестратор без вопроса: `system_status` + `find_patterns` на
текущем шаге (до 2 карточек `pattern`) + подпись от модели («Чемпион — прогон …, проверен
OPM; на шаге 96 две тревоги: …») + 4 подсказки. Кэшируется на 60 с по `(scenario, step, lang)`.

## 5. Джарвис-фронт: спецификация

### 5.1 Сфера

**Фазы на CPU.** В `useSphereRenderer` заводится `phase = {spin, flow, breath}`; каждый кадр
`phase.spin += dt * spinSpeed(energy)`, `phase.flow += dt * flowSpeed(energy)`,
`phase.breath += dt / breathPeriod(state)`. В шейдер уходят `u_spin`, `u_flow`, `u_breath`
(а не `u_time`). `energy` и `halo` не берутся из состояния напрямую, а **подтягиваются** к
целевым значениям экспоненциально (`value += (target - value) * (1 - exp(-dt/τ))`, τ = 350 мс).
Результат: hover меняет только скорость, никаких скачков.

**Молнии вместо пульса.** Периодическая волна `u_pulse` удаляется. Амплитуда дыхания
`squeeze` 2.8 % → 1.2 %, яркость ядра от дыхания ±5 %. Новый механизм — **разряды**:

| Состояние | Интервал между разрядами | Разрядов за раз | Длительность |
|---|---|---|---|
| idle | 5–11 с | 1 | 320–480 мс |
| hover | 2.5–5 с | 1–2 | 320–480 мс |
| listening | по пикам `u_audio` > 0.45, не чаще 400 мс | 1 | 260 мс |
| thinking | 1.2–2.4 с | 1–3 | 240–360 мс |
| speaking | по пикам `u_audio` > 0.35 | 1–2 | 220 мс |
| error | одна красная вспышка (как сейчас) | — | 600 мс |

Реализация: `u_bolts` — четыре `vec4(seed, start, duration, strength)`; в шейдере разряд —
тонкая ломаная по поверхности шара (great-circle от точки `seed` с шумом `fbm` по параметру),
ширина 1.5–2.5 px, ядро `--color-jarvis-rim`, ореол `--color-jarvis-pulse`, послесвечение
затухает 600 мс после конца. При hover направление разрядов тянется к курсору (`u_pointer`,
нормализованные координаты). Внутреннее облако и филаменты остаются, но тише (`vein` ×0.7).

**Светлая тема.** `u_theme` (0/1). В светлой: тонмап в премультиплицированный цвет,
`premultipliedAlpha: true`, `blendFunc(ONE, ONE_MINUS_SRC_ALPHA)`; тело — плотный тёмно-синий
градиент (`--color-jarvis-body` светлой темы), разряды бело-голубые, гало заменяется
**мягкой холодной тенью** под сферой (тёмный цвет с альфой, не свечение), кольцо — тонкая
тёмная линия. Референс — стеклянный плазменный шар на белом столе. Фолбэк-CSS тоже с двумя
ветками.

**Прочее.** `prefers-reduced-motion`: разрядов нет, статичный кадр с лёгким мерцанием.
Пауза по видимости как сейчас.

### 5.2 Раскладка экрана

```text
┌──────────────────────────────────────────────────────────────────┐
│ контекст: base · 2015-01 · скв. 45     ru/en  🔊  [TTS ✓ STT ✓]  │  лента контекста (без ×)
│                                                                   │
│        карточка          ○ сфера ○           карточка             │  орбита (до 8)
│     карточка         подпись сцены              карточка          │
│                    ▸ развёрнутый ответ (markdown, свёрнут)        │  панель ответа
│                                                                   │
│  ●──●──●──◉──○           лента памяти  [сегодня ▾]                │  history rail
│  [ подсказка ] [ подсказка ] [ подсказка ] [ подсказка ]          │
│  ┌────────────────────────────────────────────────────┐  ◉ mic   │  док ввода
│  └────────────────────────────────────────────────────┘          │
│ ┌────────┐                                                        │
│ │ ⌂ Консоль  Esc │   ← дверь: там же, где сфера в навигации       │
└──────────────────────────────────────────────────────────────────┘
```

- **Дверь** (`JarvisDoor`) — слева снизу, в точке слота лончера (`#jarvis-launcher-slot`
  геометрия совпадает по `left/bottom`). Иконка куба + «Консоль» + подсказка `Esc`. Клик —
  закрытие через угол; коллапс сферы летит к двери. Крестик из ленты убирается.
- **Лента памяти** (`HistoryRail`) — горизонтальная полоса над подсказками. Бусина = сцена:
  кружок с глифами типов карточек по дуге (до 4), под ним вопрос (обрезка 28 символов),
  справа время. Активная бусина — крупнее, дышит в фазе сферы (CSS-переменная
  `--jarvis-breath` пишется рендерером сферы раз в кадр). Между бусинами нить — SVG-путь,
  дорисовывается при появлении новой (`stroke-dashoffset`). Новая бусина «выдыхается»:
  из центра сферы к её месту летит искра (тот же `SphereBurstLayer`, режим `exhale`,
  260 мс), бусина появляется с масштабом 0.6 → 1 и вспышкой. Hover — превью-плашка над
  бусиной: мини-орбита (глифы карточек) + первая строка подписи. Клик — сцена выезжает из
  глубины (существующий `SceneStack`, который теперь управляется лентой; сама стопка
  остаётся видимой как глубина позади сферы, но без собственного списка). Клавиши: `←/→` по
  ленте, `↑/↓` как раньше, `Home/End`. Колесо над лентой — прокрутка ленты, не сцен.
  Справа — выпадающий список сессий («сегодня», «вчера», даты) из `GET /sessions`.
- **Панель ответа** (`AnswerPanel`) — под подписью, свёрнута до первой строки; разворот по
  клику или клавише `A`; внутри markdown (§5.3), max-height 40 vh со своим скроллом.
- **Возврат ввода**: `↑` в пустом поле подставляет предыдущие вопросы сессии.

### 5.3 Markdown

Свой модуль `frontend/src/jarvis/markdown/` без зависимостей: `blocks.ts` (параграфы,
заголовки, списки, fenced-код, таблицы, цитаты, горизонтальная линия), `inline.ts`
(жирный, курсив, `code`, ссылки только `http(s)`, `rel="noopener"`), `Markdown.tsx` (AST →
React-элементы, без `dangerouslySetInnerHTML`), `highlight.ts` (ключевые слова, строки,
числа, комментарии для `python`, `ts`/`js`, `bash`, `json`, `yaml`; иначе моноширинно).
Блок кода: шапка с языком, кнопка «копировать», перенос строк выключен, горизонтальный
скролл. Парсер терпим к незакрытому fence во время стрима (`answer_delta`).

### 5.4 Голос

- **Слушание**: `continuous = true`, конец фразы — по тишине: RMS из `useMicLevel` ниже
  порога 0.06 дольше 900 мс → `stop()`. Живая расшифровка — плашка над сферой
  (`LiveTranscript`), interim серым, финал белым. Режим «подтверждать»: финал попадает в поле,
  отправка по `Enter`; режим «сразу» — как сейчас; тумблер в ленте контекста, хранится в
  `localStorage`. Ошибки: `not-allowed` → подсказка «разрешите микрофон», `network` →
  переключение на серверный STT, `no-speech` → тихо. `Space` push-to-talk остаётся, `M` —
  тумблер микрофона.
- **Серверный STT**: если `SpeechRecognition` нет (Firefox/Safari) или Web Speech упал —
  `MediaRecorder` (`audio/webm;codecs=opus`, 32 kbps) → `POST /api/jarvis/transcribe`.
  Кнопка микрофона больше не скрывается никогда: если нет ни того, ни другого
  (`capabilities.stt === 'none'`) — она задизейблена с подсказкой.
- **Озвучка**: `useVoiceOutput` → `POST /api/jarvis/speak` → `AudioContext` +
  `AnalyserNode` → настоящая RMS в `u_audio` (синтетическая огибающая удаляется). Фолбэк
  `speechSynthesis` с выбором лучшего голоса (приоритет: имя содержит `Natural`/`Online`,
  затем совпадение языка), скорость 1.0. Озвучивается `caption`; кнопка «прочитать целиком»
  читает `answer` без кода. Кнопка «стоп» на статусе сцены. Если вопрос пришёл голосом —
  ответ озвучивается автоматически даже при выключенном тумблере (на один ответ). Тумблер
  и голос — в `localStorage`.

### 5.5 Без моков

- `createTransport`: вне vitest — только SSE, без `fallback`.
- `sseTransport`: ошибка сети → событие `error{code:"upstream"}`; 503 → `error{code}` из
  тела; после ошибки фронт опрашивает `health` каждые 5 с и показывает в ленте контекста
  чипы возможностей; кнопка «повторить» на `ErrorCard`.
- `vite.config.ts`: `server.proxy['/api'] = VITE_API_PROXY ?? 'http://127.0.0.1:8010'`.
- `frontend/public/jarvis/fixtures` исключаются из сборки (плагин `vite` с
  `generateBundle`-фильтром или перенос в `frontend/test-fixtures/` с правкой пути в
  `backend/application/jarvis/fixtures.py` — решает агент B, второе предпочтительнее).
- `FieldMapCard` берёт сценарий из `card.action.scenario`, а не из текущего контекста.

## 6. Консоль: исправления

### 6.1 Один корень трёх багов — контекст наложения куба

Решение: **оверлеи консоли не должны жить внутри куба.** В `JarvisStage` добавляется
сосед куба `<div id="console-overlay" className="console-overlay">` (внутри `.jarvis-stage`,
после `.jarvis-cube`, `position: fixed; inset: 0; z-index: var(--z-drawer); pointer-events: none`),
он получает `inert` и `hidden` при `transition.phase !== 'closed'`. `ConsoleInspector`
портирует **и скрим, и панель** в него (скрим `z-index: 0`, панель `z-index: 1`,
`pointer-events: auto`). `position: fixed` панели снова относительно окна, скролл
`.inspector-body` работает, скрим не накрывает панель. Проверить также `CommandPalette` и
`Popover` — если они тоже `fixed` внутри куба, перенести туда же.

Плеер: обмер геометрии не должен зависеть от `transform` предков. В `useBackdropShape`,
`useContainerBox`, `useStageBox`, `useReadoutBounds` перейти на layout-метрики
(`offsetLeft/offsetTop/offsetWidth/offsetHeight` относительно контейнера через цепочку
`offsetParent`) вместо `getBoundingClientRect()`; где нужны экранные координаты (Chronomap
readout) — брать `getBoundingClientRect()` только при `transition.phase === 'closed'`
(`useJarvis()` доступен) и один раз пересчитать на переходе в `closed`. В `applyScale`
canvas'ов — не присваивать `canvas.width`, если размер не изменился.

### 6.2 Граф: язык выделения

Один слой смысла на один визуальный признак:

| Признак | Значение |
|---|---|
| форма глифа | роль: круг — добывающая, треугольник — нагнетательная |
| заливка | полая — остановлена, сплошная — работает, серая — не введена |
