# Контракты данных — точная форма

Спецификация общих типов. Всё, что пересекает границу между пакетами, описано здесь: имена полей, единицы, порядок осей, индексация времени, инварианты.

**Чем это отличается от базы знаний.** В `docs/context/08_contracts.md` — почему контракт такой и чем проверяется. Здесь — какой он ровно. Обоснования не повторяются, ссылки на разделы вида `§2.1` ведут туда.

**Правило.** Этот каталог правит только интегратор. Нужна правка типа — issue, не коммит. Всё остальное в репозитории имеет право зависеть от написанного здесь и не имеет права это менять.

---

## 1. Общие соглашения

Ошибки в этом разделе не всплывают на компиляции и не ловятся тестами одного пакета. Они всплывают при сборке, за день до сдачи.

### 1.1 Идентификатор скважины

Строка, ровно как в `WELSPECS` дека, без кавычек: `"42"`, `"49"`, `"102"`. Не число.

Причина: приведение к `int` теряет форму, а сдаваемый `wells_schedule` обязан ссылаться на скважины идентификаторами организаторов. Всего идентификаторов 103, множество фиксировано и совпадает по `WELLTRACK`, `WELSPECS`, `COMPDATMD` и объединению `WCONPROD` с `WCONINJE`.

Порядок скважин в любом массиве — лексикографический по строке, один и тот же везде. Он задаётся один раз в `Schedule.meta.wells` и используется как ось всеми остальными типами.

### 1.2 Две шкалы времени, и это главная ловушка проекта

| Шкала | Диапазон | Начало | Кто на ней живёт |
|---|---|---|---|
| Дек | 371 шаг, индексы 0…370 | 01.11.1994 | `Response`, автомат ЭЦН |
| Управление | 225 шагов, индексы 0…224 | 01.01.2007 | `Schedule`, `Trace`, `Constraints` |

**Соответствие: `deck_index = 146 + control_index`.**

История занимает шаги 0…145. Управление начинается с шага 146 по шкале дека.

Ошибка на 146 не даст ни исключения, ни абсурдного числа — она даст правдоподобный ЧДД, посчитанный не по тем месяцам. Каждая функция, принимающая индекс шага, обязана называть шкалу в имени параметра: `control_step` или `deck_step`, никогда просто `step`.

### 1.3 Длительность шага

Шаги месячные и **неравной длины**. Границы берутся из ключевого слова `DATES` дека, а не вычисляются как 30 дней.

Накопленные величины (`WOMT`, `WLPT`, `WWIT`) приходят из симулятора нарастающим итогом; помесячный прирост берётся разностью соседних значений. Дебит (`WLPR`, `WWIR`) — мгновенный, в единицах за сутки.

Годовая агрегация в Методике ЧДД использует множитель 365 (`docs/context/04_models.md` §4). Это норматив Методики, а не наша аппроксимация, и менять его нельзя.

### 1.4 Единицы

| Величина | Единица | Примечание |
|---|---|---|
| Дебит жидкости, приёмистость, уставки | м³/сут | |
| Накопленная жидкость, накопленная закачка | м³ | |
| Накопленная и помесячная нефть | **тонны** | `WOMT` в Eclipse METRIC — масса, не объём |
| Забойное давление | бар | пределы 50 на добывающих, 300 на нагнетательных |
| Плотность | кг/м³ | нефть 913.1 и 928.2 по двум регионам, вода 1172–1173 |
| Деньги | **рубли** | не тысячи и не миллионы; ЧДД порядка 1e11 |
| Обводнённость | доля 0…1 | не проценты |
| Коэффициент дисконтирования | доля | `1/(1+0.10)^(y−2007)` |

Ни одно поле не хранит величину в производных единицах. Проценты, тысячи рублей и тонны в час — только на отображении.

### 1.5 Отсутствующие значения

`NaN` не используется нигде.

Остановленная скважина даёт `0.0` по дебиту и приёмистости, а не `NaN`. Нагнетательная имеет `0.0` по добыче. Различение «ноль» и «неприменимо» делается через роль и статус, а не через специальное значение.

Прогон, не давший данных, возвращает `RunResult` со статусом, а не массив из `NaN` (§4.4).

### 1.6 Хеши

Всё, что участвует в кешировании и воспроизводимости, хешируется SHA-256 и хранится шестнадцатеричной строкой.

Хешируются: дек после конверсии, префикс истории, каноническое расписание, `SummarySpec`, `Groups`, версия датасета, чекпоинт суррогата, конфиг.

Хеш расписания составной: `hash(история) + hash(канонические события)`. Без первой части подмена дека проходит незамеченной.

### 1.7 Поведение при невозможности посчитать

Компонент, который не может выполнить работу, **бросает исключение**. Возврат нуля, `None` или массива нужной формы со случайными значениями запрещён (§1.1 базы знаний).

Единственное исключение из правила — `RunResult`: падение симулятора это ожидаемый исход, а не ошибка, и оно передаётся статусом.

## 2. `Schedule` — расписание управления

Контракт: §2. Шкала — управления, 225 шагов.

### Состав

| Поле | Форма | Смысл |
|---|---|---|
| `meta.model` | строка | `"Model_Z"` |
| `meta.t0` | дата | `2007-01-01`, начало управления |
| `meta.n_steps` | целое | `225` |
| `meta.wells` | кортеж строк, 103 | канонический порядок скважин для всех массивов |
| `meta.history_prefix_hash` | строка | хеш неизменяемого префикса истории |
| `meta.provenance` | строка | чем порождено: параметры правила, seed |
| `initial` | отображение скважина → состояние | результат `replay(префикс)` |
| `events` | последовательность событий | канонически упорядочена |

### Начальное состояние скважины

| Поле | Форма | Значения |
|---|---|---|
| `role` | перечисление | `PROD`, `INJ` |
| `status` | перечисление | `OPEN`, `SHUT` |
| `setpoint` | вещественное | м³/сут, последняя уставка до 01.01.2007 |

Типоразмера ЭЦН здесь нет: он производный, вычисляется калькулятором ЧДД по траектории `WLPR` и хранится только там (§1.3).

### Событие

| Поле | Форма | Смысл |
|---|---|---|
| `step` | целое 0…224 | индекс по шкале управления |
| `well` | строка | идентификатор |
| `kind` | перечисление | вид решения |
| `value` | вещественное или отсутствует | м³/сут |

Виды решений:

| Вид | Требует `value` | Применим к роли |
|---|---|---|
| `SET_LRAT` | да | `PROD` |
| `SET_RATE` | да | `INJ` |
| `OPEN` | нет | любой |
| `SHUT` | нет | любой |
| `CONVERT_INJ` | нет | `PROD` |

### Инварианты

1. Канонический порядок: события отсортированы по `(step, well, kind)`, дубликаты по этому ключу удалены.
2. Одинаковое расписание даёт одинаковые байты и одинаковый хеш.
3. `SET_LRAT` не адресуется скважине, находящейся в роли `INJ` на этом шаге.
4. `CONVERT_INJ` для одной скважины встречается не более одного раза.
5. Забойное давление рычагом не является и в расписании отсутствует (§2.5).
6. Значение `0.0` у `SET_LRAT` допустимо и означает не то же самое, что `SHUT`: по Методике скважина с нулевым дебитом не является действующей, но событие остановки при этом не начисляется. Реализуется по букве Методики.

## 3. `Response` — отклик по скважинам

Контракт: §4.1, §5.1. Шкала — дека, 371 шаг. Производится и мостом, и суррогатом; типы обязаны совпадать.

### Форма

Массив с осями **`(deck_step, well, channel)`**, размер `371 × 103 × C`. Порядок осей фиксирован, порядок скважин — из `Schedule.meta.wells`.

### Каналы

| Канал | Единица | Смысл |
|---|---|---|
| `oil_mass_delta` | т | помесячный прирост `WOMT` |
| `liquid_volume_delta` | м³ | помесячный прирост `WLPT` |
| `injection_volume_delta` | м³ | помесячный прирост `WWIT` |
| `liquid_rate` | м³/сут | `WLPR` |
| `injection_rate` | м³/сут | `WWIR` |
| `bhp` | бар | `WBHP` |

Первые четыре — то, что потребляет Методика ЧДД. `WBHP` нужен динамическому валидатору и физическим проверкам суррогата.

Обводнённость каналом не является: она выводится как `1 − (oil_mass_delta / ρ) / liquid_volume_delta` и считается потребителем, чтобы не иметь двух источников истины.

### Инварианты

1. Все приросты неотрицательны: накопленные величины симулятора монотонны.
2. Скважина в роли `INJ` имеет нули по добывающим каналам, и наоборот.
3. `NaN` отсутствует.
4. Суррогат выдаёт массив той же формы и тех же каналов, что мост.

## 4. `NpvTable` — результат расчёта денег

Контракт: §3.3, §3.4. Считается за 225 шагов управления, но на вход принимает отклик за все 371.

### Три разложения

| Разложение | Ключ | Назначение |
|---|---|---|
| По годам | 2007…2025 | сдаваемое число, соответствует Методике |
| По месяцам | шаг управления 0…224 | пошаговый вывод, требование организаторов |
| По скважинам | идентификатор | диагностика, интерфейс, отключение правил |

### Статьи в каждой строке

`revenue`, `deductions`, `opex_oil`, `opex_liquid`, `opex_injection`, `opex_wellstock`, `event_costs`, `capex_esp`, `ebitda`, `fcf`, `df`, `discounted_fcf` — все в рублях, `df` безразмерный.

### Инварианты

1. Сумма месячных вкладов внутри года равна годовому дисконтированному значению с точностью до машинного нуля. Месячный ряд — разложение годового, собственной месячной ставки нет.
2. Сумма поскважинных значений равна полному ЧДД без остатка. Все нормативы Методики скважинного уровня, распределять нечего.
3. Единственная сдаваемая величина называется `npv_methodology`. Никакая другая функция слова `npv` в имени не носит.

## 5. `Constraints` — условия кейса

Контракт: §6.3. Шкала — управления. Сериализуемый документ: его порождает интерфейс, читает политика, хранит артефакт прогона.

| Раздел | Форма | Смысл |
|---|---|---|
| `injection_limits` | год → м³/сут | предел суммарной закачки |
| `liquid_limits` | год → м³/сут | предел суммарного отбора жидкости |
| `production_floors` | год → т/сут | нижняя граница добычи нефти |
| `watercut_limits` | год → доля | предел обводнённости |
| `well_outages` | скважина, шаг от, шаг до | ремонт или авария |
| `infrastructure` | свободные пары ключ-значение | лимиты КНС, товарного парка, трубопроводов |

Пустой документ означает отсутствие ограничений сверх физических, а не отсутствие данных.

## 6. `SummarySpec` и `RunResult` — работа с симулятором

Контракт: §4.3, §4.4.

`SummarySpec` — упорядоченный набор ключевых слов секции SUMMARY, которую в деке организаторов пишем мы. Имеет хеш, входящий в ключ кеша: добавленный ключ меняет форму отклика у всех потребителей.

`RunResult`:

| Поле | Форма | Смысл |
|---|---|---|
| `status` | перечисление | `OK`, `NOT_CONVERGED`, `FAILED` |
| `deck_hash`, `schedule_hash`, `summary_hash` | строки | составляют ключ кеша |
| `artifacts` | пути | выход симулятора, вне git |
| `wallclock_seconds` | вещественное | замер времени прогона |
| `message` | строка | диагностика при неуспехе |

Несошедшийся прогон — ценные данные: он означает, что расписание физически невозможно. Наружу не бросается.

## 7. `Lambda` и `Groups` — измеренная связность

Контракт: §8, §6.2.

`Lambda`:

| Поле | Форма | Смысл |
|---|---|---|
| `matrix` | `92 × 41` | влияние нагнетательной на добывающую |
| `producers`, `injectors` | кортежи строк | оси матрицы, порядок фиксирован |
| `lag_months` | целое | выбранный лаг отклика |
| `amplitude` | вещественное | доля, на которой измерялось |
| `stability` | вещественное | согласованность двух независимых партий плана |
| `achievability_ok` | логическое по скважине | добрала ли нагнетательная целевой уровень |

`achievability_ok` — не диагностика, а условие корректности: недобравшая скважина ломает ортогональность плана и роняет все оценки разом.

`Groups`: отображение идентификатор группы → набор скважин, плюс хеш и хеш породившей матрицы. Версионированный артефакт, входит в ключ кеша.

## 8. `Theta` и `Trace` — решения политики

Контракт: §6.1, §6.4.

`Theta` — вектор подгоняемых параметров, **не более 10** суммарно по всем правилам, с объявленными границами. Единственное, что видит оптимизатор.

`Trace` — запись решений. Одна запись на сработавшее правило:

| Поле | Форма |
|---|---|
| `control_step` | целое 0…224 |
| `well` | строка |
| `rule` | `R0`…`R7` |
| `inputs` | пары имя-значение, числа, по которым принято решение |
| `decision` | что сделано |

Каждое правило включается и выключается флагом. Без трассы объяснимость не работает и дисциплина отключения правил ничем не измеряется.

## 9. `RunArtifact` — то, что читает интерфейс

Контракт: §12.2. Бандл, собираемый после прогона; интерфейс не вычисляет ничего и берёт всё отсюда.

Состав: `config_hash`, `Schedule`, `Response`, `NpvTable`, `Trace`, `Groups`, `Lambda`, `Constraints`.

Интерфейс развивается против этой схемы и не зависит ни от оптимизатора, ни от симулятора. Демонстрация воспроизводит готовый артефакт, а не считает заново.

## 10. `Config` — воспроизводимость

Контракт: §11. Правило: **ни один компонент не читает параметр мимо конфига.** Запуск определяется парой «конфиг плюс данные организаторов».

| Раздел | Содержимое |
|---|---|
| `seeds` | глобальный и по компонентам |
| `policies` | налоги, начальный ЭЦН, квантование уставок, OPEX жидкости |
| `theta` | найденные значения |
| `rules` | R0…R7 включено или выключено |
| `budgets` | прогонов на раунд верификации, потолок итераций неподвижной точки |
| `hashes` | дек, префикс истории, `SummarySpec`, `Groups`, датасет, чекпоинт суррогата |

Хеш выданного дека внутри конфига доказывает, что расчёт шёл на данных организаторов.

## 11. Швы между пакетами

Кто что производит и кто это потребляет. Стрелка через контракт — единственный разрешённый способ взаимодействия.

| Тип | Производит | Потребляют |
|---|---|---|
| `Schedule` | Савелий | все |
| `wells_schedule.inc` | Савелий | Андрей |
| `NpvTable` | Савелий | Андрей, Иван, Михаил |
| `Response` | Андрей | Савелий, Иван, Михаил |
| `RunResult`, `Runner` | Андрей | Иван |
| суррогат | Андрей | Иван |
| `Lambda`, `Groups` | Иван | Андрей, Михаил |
| `Trace` | Иван | Михаил |
| `Constraints` | Михаил | Иван |
| `RunArtifact` | Михаил собирает | Михаил |

Два общих сервиса, у которых больше одного потребителя: `Runner` Андрея вызывают и генератор датасета, и измерение λ; `NpvTable` Савелия читают все три остальных пакета. Их интерфейсы менять больнее всего.
