# Спека интерфейса по задачам

Дополнение к [PLAN.md](PLAN.md). Здесь — проектные решения, которые агент исполняет, а не изобретает заново. Приёмка каждой задачи — в её карточке `../../docs/v2/tasks/frontend.md`, здесь не дублируется.

## F1. Дизайн-язык промышленной консоли

Референс пользователя — tNavigator и Petrel: плотно, тихо, монохромная рама, цвет только у величин.

**Тема.** Тёмная становится рабочей по умолчанию (нет сохранённого выбора → dark). Светлая остаётся полноценной второй темой. Базовые поверхности тёмной:

| Токен | Значение | Роль |
|---|---|---|
| `--color-bg` | `#0e1116` | фон приложения |
| `--color-surface` | `#151a21` | панель (+4–6% светлее фона) |
| `--color-surface-sunken` | `#10141a` | утопленные зоны, треки |
| `--color-border` | `#232a33` | границы низкоконтрастные |
| `--color-border-strong` | `#2f3844` | акцентные границы |
| `--color-text` | `#dde3ea` | текст (не чисто белый) |
| `--color-text-muted` | `#8a94a1` | вторичный |

Чистого чёрного и чистого белого нет нигде. Светлая тема пересчитывается на те же роли (фон `#f4f6f8`, панель `#ffffff`, текст `#1a2028`).

**Палитра величин** (единственные цветные токены, оба режима темы):

| Токен | Тёмная | Смысл |
|---|---|---|
| `--color-oil` | `#d9973f` | нефть, тёплый янтарный |
| `--color-water` | `#4fb3c9` | вода добытая, холодный циан |
| `--color-injection` | `#5b8def` | закачка, синий |
| `--color-danger` | существующий | убыток, нарушение |
| `--scale-watercut-0` | `= --color-oil` | обводнённость 0 — чистая |
| `--scale-watercut-1` | `= --color-water` | обводнённость 1 — промытая |

Шкала обводнённости — линейная интерполяция `--scale-watercut-0 → --scale-watercut-1` в OKLCH-подобном пути (функция `watercutColor(w)` в `theme/scales.ts`, одна на всё приложение: карта, хронокарта, стена, граф). Ни одного цвета без физического смысла; акцент `--color-accent` остаётся только для интерактивных состояний (фокус, выбор), не для данных.

**Типографика.** JetBrains Mono локально: `jetbrains-mono-{400,500,700}-{latin,cyrillic}.woff2` в `public/fonts`, `unicode-range` как у Inter. Токены: `--font-family-mono: 'JetBrains Mono', ui-monospace, 'Cascadia Mono', Consolas, monospace`. В `styles.css` базовым слоем: `font-variant-numeric: tabular-nums` на `body`; все числовые ячейки/значения — моноширинные (класс `num` либо селекторы таблиц).

**Плотность.** Строка таблицы 24–28px (`--size-row: 26px`), вертикальные отступы блоков вдвое меньше текущих (`--space-*` не переопределять глобально — ужать точечно в видах, это разрешено: карточка запрещает менять разметку компонентов, не значения падингов в CSS видов? Нет — карточка ограничивает задачу слоем токенов и базовых стилей, поэтому плотность закладывается новыми токенами `--space-panel-y`, `--size-row`, а виды переезжают на них в своих задачах W2–W7).

**Удаляется.** `body::before` dot-grid; `max-width`+центрирование `.app`; `border-radius: var(--radius-pill)` у кнопок (заменить на `--radius-sm: 2px`; сам токен `--radius-pill` выпилить, tokens.test.ts это фиксирует); `translateY(-2px)` на hover. Скругления по всему приложению ≤4px.

**Обновить `DESIGN.md`** в корне репозитория — он описывает токены и обязан отражать новую палитру и типографику.

**Цвета участков `--color-group-1..6` проверены валидатором скилла `dataviz`** (`scripts/validate_palette.js`), обе темы: светлота в полосе режима, цветность выше пола, контраст к холсту ≥3:1, разделение под протанопией/дейтеранопией/тританопией. Подбирались перебором в OKLCH, а не на глаз. **Менять их можно только повторным прогоном валидатора** — пары `G4`/`G6` в светлой теме идут на нижней границе нормального различения (ΔE 11.9), поэтому подпись участка рядом с цветом обязательна везде, где они используются: цвет там не единственный носитель смысла.

## F2. Карта показывает состояние

`WellsPlot.tsx` + `WellMarker.tsx` + `MapLegend.tsx` + `LayerSwitch` остаётся.

- **Радиус** — площадь пропорциональна величине: `r = clamp(rMin, rMax, k·sqrt(v / vMax))`, `rMin = 1.2`, `rMax = 4.5` (юниты viewBox), `vMax` — максимум величины по всему горизонту из данных (не по шагу — иначе карта «дышит» от нормировки, а не от физики). Добывающие — `liquid_rate`, нагнетательные — `injection_rate`.
- **Заливка** — `watercutColor(watercut)`; у нагнетательных при выборе величины «обводнённость» — `--color-injection` (у них обводнённости нет, вода закачивается).
- **Статусы:** `operating_status === 'SHUT'` — полая обводка без заливки тем же радиусом; `availability === 'NOT_COMMISSIONED'` — бледный контур (`--color-text-muted` на 35% альфы), радиус `rMin`, без заливки. Остановленная и невведённая обязаны различаться на глаз и в легенде.
- **Форма** — как сейчас: круг добывающая, треугольник нагнетательная.
- **Переключатель величины** — `SegmentedControl` (существующий): «Обводнённость | Вклад в ЧДД | Факт/цель». Вклад в ЧДД — из `npv.json` (`with_allocated_tax`, статичен по шагам, подписывается «с распределённым налогом» — §3.3); факт/цель — `fact_to_target` шкалой `--color-danger` (<1) → нейтраль (=1); заливка по выбранной величине, радиус всегда дебит/приёмистость.
- **Легенда** переписывается: ряд размеров (три опорных значения из данных), шкала обводнённости полосой, полая/бледная маркировка статусов.
- Данные только `timeline.steps[stepIndex].wells` и `npv.json`. Ничего не считать, кроме масштабирования пикселей.

## F3. Двойная проекция карта ↔ связность

Новый вид `views/FieldProjection/`: `FieldProjection.tsx`, `useProjection.ts`, `interpolate.ts`, `EdgeLayer.tsx`, css.

- Обе раскладки нормализуются в общий viewBox letterbox-приведением: карта — `I/J` из `wells.json` (ось J вниз, как принято на сетке), граф — `x/y` из `graph.json.layout.size`. Нормализация — чистая функция `fitLayout(points, box)`, тестируемая.
- Позиция узла: `p = lerp(map[i], graph[i], easedT)`. Состояние `t ∈ [0,1]` в компоненте; сегментный переключатель «Карта | Связность» анимирует к 0/1 за 1350 мс с `--ease-emphasis`; ползунок (существующий `Slider`) даёт произвольный `t`. `prefers-reduced-motion` — мгновенно.
- Анимация — `requestAnimationFrame` над числовым `t`, не CSS-переходы координат (103 узла + рёбра синхронно).
- Рёбра λ: opacity `= t` (появляются к связности), толщина — вес λ (существующая шкала из `LambdaGraph/model.ts`), порог λ ползунком переиспользуется.
- Кодировка узла — компонент/функции из F2 (`WellMarker`), чтобы обе проекции читались одинаково; заливка живёт по `stepIndex` — проекция тоже показывает состояние времени.
- Зум/пан — `useViewBox` из `LambdaGraph`.
- Узлы без координат в одной из раскладок (в демо-графе есть не все скважины из wells.json — сверить по id) — рисуются только там, где есть, с fade по `t`; молча не пропадают: счётчик «N без связности» в подписи.
- `FieldMap` и `LambdaGraph` остаются на месте до F7.

## F4. Хронокарта 103 × 225

Новый вид `views/Chronomap/`: `Chronomap.tsx`, `useChronomapCanvas.ts`, `cells.ts` (модель: величина → цвет ячейки), `sortRows.ts`, css. Всё на одном `<canvas>`, отрисовка одним проходом по `ImageData` либо `fillRect` построчно — на 103×225 оба укладываются в кадр; выбрать по замеру.

- Строка — скважина, столбец — управляющий шаг. Размеры канвы — из `steps.length` × `wells.length`, множитель `devicePixelRatio`.
- Величины (SegmentedControl): обводнённость — `watercutColor`; режим — категориальные: добыча `--color-oil`, закачка `--color-injection`, остановлена `--color-surface-sunken`, не введена `--color-bg`; факт/цель — данжер-шкала; вклад в ЧДД — статичная по столбцам заливка строки знаком (положительный нейтраль / отрицательный данжер) — честно подписать, что величина не пошаговая.
- Терминальный столбец (`terminal: true`) — штрихованная/приглушённая колонка с подписью в тултипе «состояние без интервала».
- Сортировки: по номеру (`compareWellIds`), по участку (`graph.json.groups`, скважины вне групп — в конец, явно), по вкладу в ЧДД (`npv.json`).
- Наведение — оверлейный тултип (позиция из `offsetX/offsetY` → индексы): скважина, дата шага, значение. Клик — `selectWell(well)` + `setStepIndex(step)`.
- Вертикальная линия текущего шага — отдельный тонкий оверлей (второй canvas или абсолютный div), чтобы не перерисовывать матрицу на каждом шаге воспроизведения.
- Оси: сверху годы (первый шаг каждого года из дат данных), слева номера скважин моноширинным с прореживанием по высоте строки.

## F5. Инспектор скважины

`WellCard` перестаёт быть модалкой: `<aside>` справа, в потоке разметки (не оверлей), без `aria-modal`, без backdrop, без запирания фокуса. `Escape` закрывает, фокус возвращается на вызвавший элемент (сохранить `useDeferredClose`, вырезать focus-trap).

- Новые блоки: участок скважины (из `groups`), соседи по λ выше порога — список `{сосед, λ}` по убыванию из `graph.json.edges` (для добывающей — её нагнетательные, для нагнетательной — её добывающие), бейдж окна применимости λ (`graph.window`, формулировка как в `LambdaGraph`). Клик по соседу — `selectWell(neighbor)`.
- Подсветка сцены: `WellsPlot`/`GraphPlot` при `selectedWell` подсвечивают группу (кольцо/приглушение остальных) и соседей по λ (обводка `--color-accent`); реализация — производные `useMemo(neighborsOf(selectedWell))` от `graph.json`, без вычислений физики.
- Существующие тесты `WellCard.test.tsx` адаптируются: убираются ожидания `aria-modal`/backdrop, добавляются соседи и переход по клику.

## F6. Временные ряды

Спарклайны — один компонент `ui/Sparkline/` (SVG, ширина по контейнеру, высота ~28px в агрегатах, ~40px в карточке): линия `polyline` по ряду за все шаги, маркер текущего шага, отсутствующие значения (`null`, терминальный шаг) — разрыв линии, не ноль.

- `FieldStats.tsx`: каждая из пяти величин получает спарклайн ряда из всех `steps[].field.*`; компенсация — фоновая полоса коридора из `field_norms.compensation` (см. PLAN_DATA.md; поля нет — полосы нет).
- Главный график `views/Timeline/MainChart.tsx` (SVG вручную). **Двойной оси Y нет** — правило скилла `dataviz`: две шкалы на одном полотне выдумывают корреляцию, которой в данных нет. Вместо неё — **две сложенные панели с общей осью времени** (small multiples): верхняя — накопленный ЧДД (`npv_cumulative`), нижняя — месячный отбор жидкости (`production`). У каждой своя ось Y с собственной подписью единиц, ось X одна на обе и подписана один раз внизу. Сквозной вертикальный курсор текущего шага проходит через обе панели; клик/драг по любой из них — `setStepIndex`.
- **Добычи нефти в бандле нет** — есть только `production` (жидкость). Вычислять нефть из обводнённости запрещено (§12.1), поэтому рисуется жидкость с честной подписью; поле `field.oil_production` заявлено интегратору в PLAN_DATA.md.
- Карточка скважины: три спарклайна на всю историю — `liquid_rate` (для INJ — `injection_rate`, подписано), `watercut`, `bhp`; ряды собираются один раз `useMemo` по `steps[].wells` через индекс скважины.
- Ряд строится итерацией по `steps` — длина из данных.

## F11. Совет агентов

Новый вид `views/Council/` (режим сцены), данные — `hierarchy.json` (PLAN_DATA.md).

- Три яруса сверху вниз: **поле** (полный лимит закачки и его разбиение по участкам — горизонтальная полоса, сегменты пропорциональны, числа моноширинным), **участки** (карточка на группу: получено → распределено по скважинам, топ распределения виден, остальное свёрнуто), **исполнители** (решения по скважинам выбранного участка: скважина, решение, правило, сработавшее ограничение).
- Клик по скважине (в любом виде — общий `selectedWell`) подсвечивает путь: исполнитель → его участок → сегмент поля; остальное приглушается. Ровно один путь.
- Цвет участка — те же цвета групп, что кольца в графе (`--color-group-*`).
- Смена `stepIndex` меняет числа всех ярусов — данные пошаговые.
- Скважина без группы — явная строка «вне участков» на ярусе участков, не пропадает.
- Числа не агрегируются фронтом: суммы приходят в данных готовыми (поле `total`); фронт только рисует пропорции.

## F13. Демо-режим

`app/DemoMode/`: `useDemoPlayback.ts`, `DemoCaption.tsx`, `DemoControls.tsx`. Сценарий — `public/data/demo-script.json` (форма в PLAN_DATA.md), грузится как датасет, не константы.

- Кадр: `{step, scene, well|null, event|null, hold_ms}`.
- **Имена сцен в документе и в консоли не совпадают** (проверено 20.08): `demo-script.json` пишет `"scene": "projection" | "chronomap"`, а `SCENE_MODES` в `state/ConsoleContext.tsx` — `'projection' | 'chrono'`. Нужна явная таблица соответствия в одном месте (`app/DemoMode/scenes.ts`), а не подгонка строк по месту вызова; неизвестное имя сцены — кадр пропускается и логируется, как и неподтверждённое событие. Чинить генератор ради этого не нужно: имя сцены — свойство документа, а не данных прогона. Плеер идёт по кадрам: ставит `setStepIndex` (с анимацией пробега шагов на скорости из F10), `setSceneMode`, `selectWell`; подпись рендерится из i18n-шаблона по `event.type` + данные события (номер скважины, дата из шага) — текст не сочиняется и не хранится в сценарии.
- **Проверено 20.08:** все 13 кадров текущего `demo-script.json` подтверждаются данными (12 × `RULE_FIRED` сверены с `trace.json` по паре скважина-шаг, 1 × `MORPH` подтверждения не требует), суммарная длительность 58.5 с при целевых ~60. То есть на текущем бандле фильтр не должен выбросить ни одного кадра — если выбрасывает, дефект в сверке, а не в данных.
- Валидация подписи: тип события обязан подтверждаться данными (перевод — реальная смена роли на этом шаге; ввод — реальная смена availability; правило — запись в `trace.json` на этом шаге у этой скважины). Кадр с неподтверждённым событием не показывается и логируется в консоль — тест это фиксирует.
- Счётчик накопленного ЧДД в подписи — из `steps[].field.npv_cumulative` текущего шага.
- Любое действие пользователя (клик, клавиша, колесо) — пауза; возобновление кнопкой с текущего кадра. `prefers-reduced-motion` — без пробега шагов и морфинга, мгновенная смена кадров.
- Запуск — команда в палитре (F10) и кнопка в `StepControls`. Целевая длительность ~60 с — сумма `holdMs` сценария, тест проверяет диапазон.

## F14. Стена жизней

Новый вид `views/WallOfLives/` (режим сцены), canvas одним проходом.

- Сетка миниатюр: колонка ~120×36px на скважину, число колонок из ширины контейнера, всё из `wells.length`. На миниатюре: линия дебита (для INJ — приёмистости, оттенок роли), заливка под линией — обводнённость (`watercutColor` по последнему значению или градиент по X запрещён — заливка сплошная цветом текущей обводнённости шага? Нет: заливка области под линией цветом `watercutColor(w[t])` поколоночно — это категориально по X, не декоративный градиент: каждый пиксель X кодирует измеренную величину этого шага), вертикальные засечки остановок (`operating_status` SHUT-переходы).
- Подпись миниатюры: номер моноширинным + вклад в ЧДД при соответствующей сортировке.
- Сортировки (SegmentedControl): номер, участок, вклад в ЧДД, обводнённость на последнем наблюдаемом шаге — всё готовыми данными (`compareWellIds`, `groups`, `npv.json`, последний не-терминальный шаг).
- Общая вертикальная линия текущего шага на всех миниатюрах — оверлей поверх канвы, синхронно с `TimelineContext`; перерисовка матрицы только при смене сортировки/величины/размера.
- Клик по миниатюре — `selectWell` (инспектор F5 открывается сам).
- Наведение — подсветка рамки миниатюры + номер.

## F15. Вклад правил в деньги

Блок «Вклад правил» внутри вкладки «Рейтинг ЧДД» (деньги к деньгам, новый таб не заводится). Данные — `ablation.json` (PLAN_DATA.md).

- Таблица R0–R7: правило, формулировка на языке промысла (i18n, тексты из концепта §6 — «Вода течёт к тем скважинам, где она превращается в нефть» и т.д.), флаг (вкл/выкл), дельта ЧДД при выключении, доля от итога полосой.
- `delta === null` → «не измерено» (muted), не ноль и не пустая ячейка. `delta === 0` при `measured` → явное «0 — кандидат на удаление» (это результат).
- Выключенное правило визуально отличимо от нулевого вклада: строка приглушена целиком + бейдж «выключено».
- R7: «реализовано, выключено — выгода данными не подтверждена» из `disabled_reason`.
- Согласованность суммы долей и итога проверяется тестом на фикстуре — но не вычисляется в рендере: показываются присланные значения.
