Фронт ничего не вычисляет — недостающее добавляется в экспортёры `ui/` задачей **D1** (волна W2, агент Б). `ui/` принадлежит интегратору (Савелию) с 20.08 — D1 оформляется отдельными правками с тестами в `ui/tests/`, и Савелий ставится в известность до пуша; формы полей фиксируются здесь, чтобы реальный артефакт (`ui/base_artifact.py`) экспортировал их так же, как демо-генератор.

## Дыры и формы (задача D1)

### 1. `hierarchy.json` — для F11 (scope: scenario)

Демо-генератор синтезирует по образу `policy/hierarchy.py::LeveledTraceEntry` (уровни FIELD/GROUP/WELL); реальный экспорт позже собирается из `HierarchyTrace` артефакта.

```json
{
  "meta": { "kind": "hierarchy", "provenance": "…", "synthetic": true },
  "steps": [
    {
      "control_step": 0,
      "field": {
        "injection_limit_m3_per_day": 4200.0,
        "water_available_m3_per_day": 4600.0,
        "allocations": [ { "group": "G1", "limit_m3_per_day": 830.0 } ]
      },
      "groups": [
        {
          "group": "G1",
          "received_m3_per_day": 830.0,
          "allocations": [ { "well": "1", "value_m3_per_day": 164.7 } ]
        }
      ],
      "wells": [
        {
          "well": "1", "group": "G1",
          "decision": "SET_RATE 164.7", "rule": "R1",
          "inputs": { "marginal_value": 212.4 },
          "constraint": "BHP_CEILING" 
        }
      ],
      "ungrouped": [ "45" ]
    }
  ]
}
```

Правила формы: суммы уровней согласованы в данных (фронт не пересчитывает и не проверяет — проверяет тест генератора в `ui/tests`); `constraint` — `null`, если физическое ограничение не срабатывало; `ungrouped` перечислен явно. Размер при 225 шагах × 103 скважинах с компактными сепараторами ≈ 3–4 МБ — грузится лениво только видом «Совет» (виды и так lazy).

### 2. `ablation.json` — для F15 (scope: scenario)

```json
{
  "meta": { "kind": "ablation" },
  "npv_total": 141177.26,
  "rules": [
    { "rule": "R0", "enabled": true,  "delta_npv": 12840.0, "share": 0.091 },
    { "rule": "R5", "enabled": true,  "delta_npv": 0.0,     "share": 0.0 },
    { "rule": "R2", "enabled": true,  "delta_npv": null,    "share": null },
    { "rule": "R7", "enabled": false, "delta_npv": null,    "share": null,
      "disabled_reason": "UPLIFT_NOT_MEASURED" }
  ]
}
```

`delta_npv: null` = не измерено; `0.0` = измеренный ноль — фронт обязан различать. Источник реальных значений в будущем — `policy/trace.py::ablation_delta`; демо-генератор даёт правдоподобные величины с обязательным null-случаем и нулевым случаем, чтобы фронт их рендерил не по счастливой случайности. Формулировки правил — не в данных, а в i18n фронта (тексты из `07_concept.md` §6).

### 3. Расширение `scenarios.json` — для F8

К каждому сценарию добавляются поля (все допускают `null`):

```json
{
  "ood_score": 0.18, "ood_threshold": 0.5,
  "worst_regret": { "scenario_id": "S-07", "value_rub": 201000000.0, "part": "holdout" },
  "final_npv": null
}
```

`final_npv` заполненный: `{ "npv_rub": 10786000000.0, "run_id": "…" }` — только у сданного артефакта (§12.2). Демо: у `base` — `null` + измеренные ood/regret, у `whatif` — все три `null` (фронт показывает «не измерено» и «прогноз»). Типы фронта расширяются опционально, валидатор терпим к отсутствию.

### 4. `field_norms` в `timeline.json` — для F6

Верхнеуровневое поле рядом с `wells`:

```json
"field_norms": { "compensation": { "min": 0.95, "max": 1.15 } }
```

Коридор — параметр политики (R5), приходит из артефакта; демо пишет правдоподобный. Поля нет — фронт не рисует полосу.

### 5. `demo-script.json` — для F13 (scope: root)

Авторский документ (выбор кадров — ручной, текст — нет):

```json
{
  "meta": { "kind": "demo-script" },
  "frames": [
    { "step": 0,   "scene": "projection", "t": 0,   "well": null,
      "event": null, "hold_ms": 4000 },
    { "step": 0,   "scene": "projection", "t": 1,   "well": null,
      "event": { "type": "MORPH" }, "hold_ms": 5000 },
    { "step": 60,  "scene": "projection", "well": "71",
      "event": { "type": "COMMISSIONED", "well": "71" }, "hold_ms": 4000 },
    { "step": 118, "scene": "chronomap", "well": "42",
      "event": { "type": "ROLE_CHANGE", "well": "42" }, "hold_ms": 5000 },
    { "step": 150, "scene": "projection", "well": "2",
      "event": { "type": "RULE_FIRED", "well": "2", "rule": "R1" }, "hold_ms": 5000 }
  ]
}
```

Типы событий: `COMMISSIONED`, `ROLE_CHANGE`, `SHUT`, `RULE_FIRED`, `MORPH`. Каждое (кроме `MORPH`) фронт сверяет с данными шага; неподтверждённый кадр пропускается. Конкретные шаги/скважины в сценарии подбираются после D1 по реальному содержимому демо-бандла (скрипт-помощник в `ui/` печатает список событий — из него автор выбирает).

### 5а. Находка 20.08: в демо-бандле ноль событий фонда

Замер по `public/data/timeline.json`: за все 225 шагов **ни одного** ввода скважины, перевода под закачку или перехода в остановку. 22 невведённых и 22 остановленных стоят так с первого шага до последнего; `role`, `availability` и `operating_status` не меняются вообще. Меняются только числа — дебиты, обводнённость, давления.

Три следствия, которые нельзя списать на недоделку фронта:

1. **F7, отметки событий на шкале времени.** Отмечать нечего. Шкала делает годы и терминальный шаг, а слой событий пишется так, чтобы отрисоваться при их появлении и молча отсутствовать сейчас. Пустая шкала — верный показ пустых данных, а не баг.
2. **F13, подписи ролика.** Из пяти типов событий подтверждаются данными только `RULE_FIRED` и синтетический `MORPH`. `COMMISSIONED`/`ROLE_CHANGE`/`SHUT` в кадры не попадают — и правильно, карточка требует брать подписи из данных, а не сочинять.
3. **Заявка интегратору.** На настоящем `RunArtifact` события обязаны быть: дек вводит 22 скважины внутри горизонта (`04_models.md` §3), а политика переводит скважины под закачку правилом R6. Если их не окажется и там — это дефект экспортёра или самого прогона, а не витрины. Проверять на первом же непустом артефакте.

### 5б. Находка 20.08: компенсация вне коридора на всех 224 шагах

Замер по демо-бандлу: компенсация лежит в 0.448…0.603 при среднем 0.518, коридор нормы — 0.95…1.15. **Внутрь коридора не попадает ни один шаг из 224.** Найдено при реализации F6: полоса коридора сначала не рисовалась вовсе, потому что не пересекалась с рядом (`Sparkline` строил рамку только по ряду и нижней границе — исправлено, рамка теперь берётся по более широкой из двух).

Для синтетики это не дефект витрины: числа демонстрационные. Но проверять на реальном артефакте обязательно, потому что физически это означает, что отбор вдвое превышает закачку — хроническое недокомпенсирование, при котором пластовое давление падает. Если то же самое покажет настоящий прогон, вопрос уже не к интерфейсу, а к политике R5 «Держим компенсацию участка в коридоре»: либо коридор в артефакте не тот, либо правило не удерживает. Витрина своё дело сделает — она это показывает, а не прячет.

### 6. Заявка без реализации: месячная добыча нефти

Главному графику F6 честно нужна месячная нефть, в бандле есть только жидкость (`production`). Вычислять из обводнённости фронту запрещено (§12.1). D1 её **не** добавляет самовольно — это заявка интегратору: поле `field.oil_production` в `steps[]`, источник — `IntervalResponse`. Пока его нет, главный график показывает отбор жидкости с подписью.
