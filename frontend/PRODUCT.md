# AIOS — консоль управления нефтяным месторождением

## Register

**Product.** Дизайн обслуживает продукт, а не является им. Это рабочий инструмент: оператор
смотрит на него сменами, а не «посещает» его. Все сигналы продуктовые — app-shell с боковой
навигацией, плотные таблицы данных, временная шкала, панель-инспектор, десять экранов под
одним каркасом (`overview`, `field`, `history`, `decisions`, `money`). Ни одной маркетинговой
поверхности: нет лендинга, нет hero-секций, нет `/pricing`.

## Target users

Инженер-разработчик месторождения и оператор ППД. Профессионал, который знает предметную
область лучше, чем интерфейс: ему не нужно объяснять, что такое забойное давление или
обводнённость. Ему нужно за секунды увидеть, **что система решила и почему**.

Условия работы: рабочая станция, широкий монитор (1500-2400px), долгие сессии, часто в
помещении с ярким верхним светом — поэтому светлая тема не «на всякий случай», а основной
режим; тёмная нужна для ночных смен.

## Purpose

Показать решения автоматического распределения закачки по скважинам так, чтобы человек мог их
**проверить и оспорить**. Ключевой инвариант проекта: компонент, который не может посчитать
результат, обязан сообщить об ошибке, а не подставить правдоподобное число. Интерфейс наследует
это требование — он не имеет права выглядеть уверенно там, где данных нет.

## Brand personality

Приборная панель, а не приложение. Плотно, спокойно, без украшательства. Цвет — носитель смысла
(нефть / вода / закачка / участок), а не декор. Числа моноширинные и выровненные, потому что их
сравнивают глазами по колонке.

Одно отступление от аскетизма сделано намеренно: цвета живые и насыщенные, а углы заметно
скруглены. Предыдущая версия была технически корректной, но выглядела мёртвой — приглушённые
охристые тона и 4-пиксельные углы читались как незаконченный прототип.

## Anti-references

- **SaaS-дашборд с карточками-плитками.** Одинаковые карточки «иконка + заголовок + число» —
  ровно то, чего здесь быть не должно: у величин разный вес и разная природа.
- **Hero-метрика.** Огромное число с подписью — жест маркетинга, а не диспетчерской.
- **Тусклая «профессиональная» серость.** Именно из неё проект и вытаскивают.
- **Тёмная тема по умолчанию «потому что инструмент».** Здесь свет в помещении, а не хакерский
  подвал.
- **Градиентный текст, стеклянные панели, боковые цветные полоски.** Ничего из этого.

## Strategic design principles

1. **Цвет обязан нести смысл.** Шесть участков различаются оттенком с шагом ≥30°, а концы
   шкалы обводнённости — ещё и светлотой, чтобы шкала читалась монохромно.
2. **Читаемость проверяется арифметикой, а не глазами.** Контраст 4.5:1 для текста и 3:1 для
   акцента зафиксирован тестами в `src/theme/tokens.test.ts`; палитру нельзя поменять так,
   чтобы тесты этого не заметили.
3. **Один участок — один цвет в обеих темах.** Переключение темы меняет светлоту фона, но не
   идентичность объекта.
4. **Ширина экрана принадлежит данным.** Лимит длины строки (78ch) — только для пояснительной
   прозы; таблицы, карты и панели занимают всё доступное.
5. **Движение объясняет структуру.** Появление со stagger показывает, что элементы —
   последовательность, а не куча. `prefers-reduced-motion` отключает всё.

## Accessibility

Контраст WCAG AA обязателен и покрыт тестами. Управление с клавиатуры и `focus-visible` —
обязательны. Интерфейс двуязычный (ru / en), словари плоские, в JSON.

## Tech

React 19 + TypeScript + Vite. Роутинг по History API на чистых путях (`/decisions/rules`),
без библиотеки; SPA-fallback даёт `SpaRequestHandler` в `backend/presentation/cli/web.py`. Vitest + Testing Library,
запуск на Node 22.11.0. Токены дизайна — в `src/theme/`, hex-цвета вне этого слоя запрещены
тестом.
